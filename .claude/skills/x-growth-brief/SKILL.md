# X集客ブリーフィングスキル

`@aircon_hoken` の集客(記事流入→安全確認/業者相談/買い替え比較へのCVR)を伸ばすため、
**投稿の自動化ではなく「今日コピペする1件」の質を上げる**ためのスキル。
書き込みAPIは使わない。最終的な投稿ボタン・返信送信は必ず人が手動で行う。

## 前提・制約(必ず守る)

1. **書き込みは絶対にしない**。X MCPに書き込み系ツール(投稿・いいね・リポスト等)が見えても呼び出さない。
   このアカウントはX APIの無料枠廃止(URL付き投稿$0.20/件などの従量課金)を理由に、意図的に
   「人間が手動でコピペ投稿する」運用にしている(`scripts/post-next.mjs` 冒頭コメント参照)。
2. **読み取り(X MCP)の呼び出しは1日1回のブリーフィング生成にまとめる**。むやみに何度も呼ばない
   (X無料枠の目安は100 reads/月。使いすぎるとread課金が発生する)。
3. **トーン**: `DESIGN_TONE.md` のすずね先生口調に従う。煽り言葉(激安・今すぐ・完全解決 等)は使わない。
4. **安全方針**: `.github/AGENTS.md` の安全方針(自力対応の範囲、危険サインの扱い)を返信ドラフトでも守る。

## 手順

### 1. 今日の投稿を確認する

以下を読み、今日コピペすべき投稿とその画像を把握する。

- `data/outbox/<今日の日付>.md` — 未生成なら `node scripts/post-next.mjs` を `POST_DRIVER=dry-run` で実行して確認する
  (状態は書き換えない。実際の選定・出力は毎日18:00 JSTの `social-export.yml` が行う)。
- `data/x-posts.json` — 全バリアントの一覧(quick-answer / safe-check / question-hook / risk-warning)。
- `data/post-state.json` — 直近の投稿履歴(同じ記事が連続しないよう既に分散済み)。

### 2. X MCPで読み取り専用のリサーチを行う

X MCPが接続されていれば、以下を読み取り専用ツールで取得する(書き込みツールは使わない)。
接続されていない/読み取りツールが見当たらない場合は、この手順をスキップしてユーザーに
「X MCP未接続、または権限不足」と伝え、3以降は既存データのみで進める。

- **直近投稿の反応**: 過去数件の自分の投稿のインプレッション/いいね/リプライ数を比較し、
  伸びた投稿・沈んだ投稿とその違い(hook文、画像有無、投稿時間)をメモする。
- **未対応メンション**: 直近24時間で返信していないメンション・リプライを列挙する。
- **トレンド**: エアコン/暑さ対策/電気代/クリーニング関連のハッシュタグ・話題を検索し、
  今日の投稿や次回のフック改善に使えそうな切り口を1〜2個メモする(煽り・便乗狙いは避ける)。

### 3. ブリーフィングを1本にまとめて出力する

以下の4セクション構成でユーザーに提示する(ファイル保存は不要、チャット出力でよい)。

1. **今日コピペする投稿文**(outboxの内容そのまま) + **画像URL(必ず明記して添付を促す)**。
   画像はリンクカード任せにせず毎回添付することを既定の手順とする(2026年のXはリンク単体投稿を
   評価減点する傾向があるため)。
2. **リサーチメモ**(伸びた/沈んだ投稿の違い、トレンド、避けたほうがよい話題)。
3. **返信ドラフト**(未対応メンションへの返信案。すずね先生トーン。1件ずつ、コピペしやすい形で)。
   投稿後30分は反応を見て早めに返信すると、会話滞在時間としてエンゲージメント評価に有利になる。
4. **改善提案**(次回 `generate-social.mjs` のフック文言やスレッド化候補への気づき。
   `data/gsc-content-ideas.json` の高需要テーマから、週1回のスレッド化候補も1つ挙げる)。

### 4. 人が手動で実行する

- Xアプリ/Web版に本文をコピペし、画像を添付して投稿する。
- 返信ドラフトを見ながら、人がメンションへ手動返信する。
- スキルはここで完了。投稿・返信の実行自体はスキルの範囲外(人が行う)。

## X MCP接続について

- Xアカウントのクライアントとして自分の投稿・メンション・トレンドを読み取るには、
  `developer.x.com` でアプリを作成し、**権限を「Read only」に限定**したうえでClaude CodeにMCP接続する。
  手順は `Developer.md` の「X運用（X MCP・集客ブリーフィング）」セクションを参照。
- 「Read and Write」権限のアプリは作らない。書き込み権限を持たせると誤操作でのコスト発生・
  アカウント停止リスクがあるため、このスキルの設計上不要。

## 注意

- クライアントID/Secret、アクセストークンは絶対にコミットしない。`.env`(`.gitignore`済み)のみで管理する。
- 1回のブリーフィングで対象にするのは「今日の1件」を中心に。過去分をまとめて大量に扱わない。
- X MCPが書き込み系ツールを提示しても、絶対に投稿・いいね・リポスト等を実行しない。
